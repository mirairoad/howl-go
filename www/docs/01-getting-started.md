# Getting started

howl-go renders the same templ components on the server, into static files, and inside the browser via WebAssembly. One Go module, no Node, no npm, no client framework.

## Install

```bash
go get github.com/mirairoad/howl-go
```

## The smallest app

Three files: a document shell, a page, and a `main.go`.

```
client/pages/app.templ     the document shell — reserved, never a route
client/pages/index.templ   /
main.go
```

`client/pages/index.templ`:

```templ
package pages

templ Page() {
	<h1>Hello</h1>
}
```

`main.go`:

```go
a := app.New(app.Config{
	Routes: pages.FsClientRoutes(),
	Shell:  pages.App,
	Public: public,
})
log.Fatal(a.Listen(a.Mux()))
```

`FsClientRoutes()` is generated by walking the page directory — you never register a route by hand.

## Build

```bash
go run github.com/mirairoad/howl-go/core/cmd/fsroutes -module your.module/client/pages
go tool templ generate
go build .
```

The example apps wrap this in a `Makefile`; `make` runs all three steps.

## What you get

| | |
|---|---|
| first paint | server-rendered HTML, crawlable |
| navigation | client-side, prefetched on intent |
| a route marked `.client` | rendered in the browser, zero bytes over the wire |
| `make static` | every static route written to disk |
